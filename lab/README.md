# PFAP Lab

## 结果导出

- 实验管理中的“实验报告 HTML / CSV 数据包 / JSON”导出整个实验；单次自动运行卡片中的对应入口仅导出该次运行。
- `GET /api/experiments/{id}/report?format=html|csv|json`；`GET /api/workloads/{id}/report?format=html|csv|json`。实验导出默认 JSON，下载 schemaVersion=2；运行报告不带 format 时仍是页面使用的窗口统计接口，但 workload 配置也经过字段白名单处理。
- HTML 可直接阅读并打印为 PDF。CSV 下载为 ZIP，包含 metrics、transactions、blocks、minutes、events 五张表以及 report.html / report.json。指标表附单位、样本数、定义、公式和缺失说明；各次运行独立展示，不平均 TPS / 分位数。历史传统负载没有正式窗口，不伪造稳态指标。
- 导出排除凭据、SSH 身份文件路径、私密 SN / 承诺 / 证明 / 隐私余额、原始命令 / Receipt / 错误日志 / 事件正文。事件保留时间、类别、级别；异常保留分类标记。CSV 对公式前导字符加单引号保护。
- 构建档案明确标记为导出时当前档案，不冒充历史运行包的构建证据；服务器当前配置与运行开始时保存的配置快照分别保留。缺失耗时为 null / 空值，不能解读为零开销。

PFAP Lab 是 PFAP 多节点实验的 Web 控制面。它可以在本机或多台 SSH 服务器上部署同一份不可变 runtime，启动每台机器上的多个 geth 节点，建立 full-mesh 网络，执行预设交易或自动负载，并保存交易凭证、账户状态及性能数据。

当前实现面向单实验人员、可信局域网和可复现实验，不是公网多租户平台。

真实端到端验证过程与已知限制见 [`VALIDATION_20260908.md`](VALIDATION_20260908.md)。短时功能通过不等同于高负载或统计平稳验证；目前 Transfer 的跨账户对并发存在状态树根变化风险，验证使用一对交易节点串行、矿工与观察节点独立。

## 快速开始

在仓库根目录执行：

```bash
cd /home/percy/pfap/PFAP

# geth / C++ 有变化时重建对应组件；仅 Web 变化可跳过 geth
./build.sh geth
./build.sh bundle
./build.sh lab

# 监听所有网卡，适合可信局域网
./lab/run-lan.sh
```

`run-lan.sh` 默认监听 `0.0.0.0:8090`，首次启动会生成随机 Web 密码到 `lab/data/password`。密码不会写入项目文档，该文件权限应保持 `0600`。控制服务重启后登录 Cookie 会失效，需要重新登录。

### 新控制机首次安装（推荐）

控制机负责编译 runtime、运行 Web 控制面并通过 SSH 管理 worker。兼容 runtime 的 C/C++ 部分在 Ubuntu 22.04 Docker 镜像中编译；Go 1.24 工具链从控制机只读挂载到容器。控制机需要 `docker`、`go 1.24`、`git`、`bash` 和 `sha256sum`，不要求宿主机安装 libsnark 的 C++ 依赖。

```bash
git clone <PFAP repository URL>
cd PFAP

# 首次会构建 Ubuntu 22.04 编译镜像；之后复用 Docker 和增量编译缓存
./scripts/build-compatible-runtime.sh

# 构建并启动 Web 控制面
./build.sh lab
./lab/run-lan.sh
```

成功后应存在 `dist/pfap-runtime.tar.gz` 和对应的 `.sha256` 文件。可在相同基线容器中做启动检查：

```bash
docker run --rm -v "$PWD/dist:/dist:ro" pfap-runtime-builder:ubuntu22 \
  bash -lc 'mkdir /tmp/pfap && tar -xzf /dist/pfap-runtime.tar.gz -C /tmp/pfap && \
  LD_LIBRARY_PATH=/tmp/pfap/pfap-runtime/lib /tmp/pfap/pfap-runtime/bin/geth version'
```

不要在普通更新中执行 `./build.sh keys`：重新生成 pk/vk 会改变证明参数。只有电路约束改变并计划创建全新实验网络时才应重新生成密钥。

需要明确轮换密钥时，先停止所有使用旧 runtime 的实验，再执行：

```bash
./scripts/build-compatible-runtime.sh --generate-keys
```

该命令会在兼容容器中生成四类交易的 pk/vk、写入 `dist/build-profile.json`、重新构建并打包 runtime。Lab 部署时按 runtime SHA 将同一套密钥分发给实验的所有节点。

可参考 [`lab.env.example`](lab.env.example) 设置自定义端口和数据路径。直接以 loopback 方式运行：

```bash
./bin/pfap-lab \
  -listen 127.0.0.1:8090 \
  -data ./lab/data/lab.json \
  -password-file ./lab/data/password
```

## 构建产物

| 产物 | 说明 |
| --- | --- |
| `bin/geth` | 支持 PFAP RPC 的 geth |
| `bin/pfap-lab` | Web 控制服务，静态页面已嵌入二进制 |
| `dist/pfap-runtime.tar.gz` | 多服务器部署包，包含 geth、动态库和同一套 `prfKey` |
| `lab/data/lab.json` | 实验、交易、Receipt、快照和负载状态 |
| `lab/worker/artifacts/<sha>/` | 本机 worker 按 SHA-256 缓存的 runtime |
| `lab/worker/experiments/<id>/` | 节点 datadir、IPC、PID 与日志 |

同一网络的所有节点必须使用完全相同的 runtime SHA 和 `prfKey`。

维护中的兼容性恢复补丁是例外：必须保持电路和 pk/vk 完全一致，不改变共识规则。实验的原 `artifactSha` 不覆盖；`recoveryArtifactSha` 记录已预置的恢复包，节点只有实际重启后才记录新的 `runtimeSha`。健康进程不因配置恢复包而重启，报告会保留这些版本信息。不要用这个机制混用不同电路或重新生成的密钥。

## 服务器与部署

### 本机 worker

在“服务器”页面添加：

- 主机：`local`
- 工作目录：当前用户可写目录，例如 `/home/percy/pfap/PFAP/lab/worker`
- P2P 公告地址：其他服务器能访问的本机局域网 IP

本机执行不经过 SSH，但与远端 worker 使用相同的 artifact 缓存、端口检查和实验隔离结构。

### SSH worker

每台远端服务器需要：

- 专用非特权用户和可写工作目录；
- 已加入 `known_hosts` 的主机密钥；
- 非交互式密钥认证；
- `bash`、`tar`、`sha256sum`、`setsid`、`ss`；单节点恢复还需要 `timeout`、`flock`，建议安装 `fuser`（未安装时使用 `/proc` 检查目录占用）；
- 实验前完成时钟同步；
- 防火墙允许实验使用的 P2P 端口。

推荐的 worker 基线是 `x86_64/amd64`、Ubuntu 22.04 或更新版本（glibc 不低于 2.35）。worker 不需要 Docker、Go、GCC、CMake、libsnark 源码或 GMP 开发包；geth 和所需的 C++/GMP 运行库都包含在 runtime 中。ARM64 或 glibc 低于 2.35 的机器需要单独的构建产物，不能直接混入当前实验。

新增一台 worker 的参考准备命令（用户名和路径可自行替换）：

```bash
sudo useradd --create-home --shell /bin/bash pfap
sudo install -d -o pfap -g pfap /opt/pfap-worker
sudo apt-get update
sudo apt-get install -y openssh-server bash tar coreutils util-linux iproute2 psmisc
```

将控制机公钥加入 worker 的 `/home/pfap/.ssh/authorized_keys`，并确认可非交互登录：

```bash
ssh -i /path/to/private_key pfap@WORKER_IP 'uname -m; getconf GNU_LIBC_VERSION; command -v bash tar sha256sum setsid ss'
```

随后在 Lab“服务器”页面添加：主机地址、SSH 端口、用户 `pfap`、私钥路径、工作目录 `/opt/pfap-worker`，以及其他节点能访问的 P2P 公告地址。点击“信任 SSH 主机密钥”，通过可信渠道核对指纹后再保存；然后点击“检查连接”。控制面会在正式上传和创建账户前检查架构、glibc、动态库及命令依赖。

防火墙至少需要允许控制机访问 SSH，并允许实验节点之间访问所分配的 P2P TCP/UDP 端口。RPC 默认只供控制面使用，不应直接暴露到公网。

首次连接采用 TOFU 保存主机密钥，控制面不会关闭 `StrictHostKeyChecking`。更换或重装服务器后若主机密钥变化，必须先核对新指纹，不能直接绕过告警。

服务器页面支持编辑、删除和批量添加。批量添加接受换行、逗号、空格或分号分隔的 IP/主机名列表，并为它们应用同一套 SSH 用户、端口、私钥、工作目录及宿主机归属；后端会先完成全部校验再一次性保存，最多 100 台。活动实验使用的服务器仍可修改显示名称和宿主机归属，连接信息必须在实验停止后修改。服务器被活动或草稿实验引用时不能删除；只被已停止/失败的历史实验引用时可以删除配置，历史实验数据不会被级联删除，远端文件也不会被删除。

服务器列表默认每页 10 台，可选择 20 / 50 台，并按名称、IP 或添加时间排序。支持名称/IP/宿主机搜索、连接状态与磁盘告警筛选；周期刷新保留当前页、筛选和选择。详情按需展开，添加、编辑和批量创建通过弹窗操作，不再固定占用状态列表宽度。

“全选本页”只影响当前页；跨页选择会保留，并显示不在当前页的选中数量。批量信任、删除和设置宿主机均作用于全部明确选中项，确认时列出目标；可先清空选择以避免把上一页的项目带入下一次操作。单次批量操作最多 100 台。

LXC 场景请主动填写 `hostGroup`，例如同属一台物理主机的容器均填 `pve-01`。该字段只是用户维护的归属信息，不会连接宿主机，也不通过容器 IP 猜测物理拓扑。可以批量设置已有服务器的归属；留空表示未知，显式清空需要提交空字符串。归属编辑不会重启节点或重新分配现有矿工。

双网卡服务器可在“编辑服务器 → 实验通信地址（P2P）→ 读取服务器网卡”选择实验网络地址。读取使用已保存的 SSH 配置（`local` 直接在管理机执行只读查询），展示已启用且非 DOWN 网卡的非回环、非链路本地 IPv4 地址，不自动选择或保存。读取失败时可手动填写。这里保存的是 P2P 通告地址，不是系统网卡绑定，不修改默认路由、SSH 或 Web 监听；网卡上存在该地址也不代表其他节点一定可达。新服务器先保存 SSH 配置后再读取；IPv6 自动组网暂不在此选择器范围内。相关实验仍活动或停止尚未确认时，只能查看网卡，不能修改通信地址。已有实验应先安全停止，保存新地址，再按原目录恢复并检查 peers；不会自动热切换网络或重建账户。

停止实验遇到维护时会等待当前持锁任务安全结束（最多 90 秒），等待期间新的自动日志检查会让路；前端保持操作中的提示，避免重复提交。超时表示尚未提交停止，不强行释放维护锁，也不绕过远端清理/日志归档的安全期限。真正的部署、恢复、矿工调整等生命周期冲突仍按原规则保护。

runtime 缓存在 `<workDir>/artifacts/<sha256>`；实验位于 `<workDir>/experiments/<experiment-id>`。同一主机的多个节点使用不同 datadir、P2P/RPC 端口，共享只读 runtime、证明密钥和 Ethash DAG。

P2P/RPC 起始端口填 `0` 时自动分配。首次部署前检查端口冲突并保存运行包 SHA 和节点清单；已有节点的实验继续运行时保留原端口、原目录和原运行包。若原端口被其他进程占用，先处理冲突再继续。

### 磁盘空间与历史 DAG

服务器卡片同时显示磁盘使用率、可用 GiB 和实际采样目录；工作目录尚未创建时检查最近的已存在父目录所在文件系统。空间状态与 SSH 连接状态分开展示。可用空间不超过 10% 或少于 3 GiB 时告警，不超过 5% 或少于 1 GiB 时显示严重告警；超过 2 分钟的采样标为过期。全局告警及相关实验的部署、矿工配置区均可打开“磁盘管理”。

部署、按原目录恢复、单节点恢复和启用矿工前会重新检查空间与 inode。普通节点至少预留 1 GiB 和 1024 个可用 inode；每台 worker 的矿工按最后观测区块预留 `1 GiB + N ×（当前与下一 epoch 的 DAG 上界）`，N 为涉及的矿工数。同一服务器虽然共享 DAG 目录，冷启动时多个矿工仍可能各自生成临时文件，因此不能只预留一份。epoch 0 时 1 个矿工需要 `3 GiB + 8 MiB`，2 个需要 `5 GiB + 16 MiB`；此后每 epoch 每个矿工增加 16 MiB（epoch = 区块高度 / 30000，向下取整）。部署还加上 runtime 压缩包和解压内容的大小。现存 DAG 不抵扣预留量，避免把未完成的生成文件当成完整缓存。这些检查是当时的保守准入检查，不能保证后续日志、链增长或其他程序不会耗尽磁盘。

新实验在任何 worker 写入前因磁盘或压缩包预检失败，会保留配置与错误原因、清除本次尚未使用的规划清单并回到草稿；排除问题后可再次“部署新实验”。此路径不停止节点、不创建或删除远端目录。只有状态仍属于同一次全新部署时才允许恢复草稿；已中断、已启动或节点清单发生变化时保留现有状态，不能当作全新实验覆盖。

“磁盘管理”先只读检查文件系统和候选缓存，默认不选择任何项目。只列入 Lab 仍保存实验及原部署清单、所有节点均已确认停止、没有执行中或待核验交易的历史实验，目录必须是 `<workDir>/experiments/<experiment-id>/<原 server-id>/ethash`。服务器重新注册后，仍按原部署 ID 识别目录；未知目录和已经删除实验记录的缓存不会自动纳入。

检查结果在控制进程内保存 10 分钟，重新检查会替换旧结果，控制器重启后失效。提交只接受该次检查中的明确选择；服务端重新核对服务器配置、原部署清单、全部节点状态及文件指纹，忽略客户端填写的字节数。清理获准执行后检查记录立即失效，部分失败也必须重新检查。执行期间与部署、恢复和矿工调整互斥，并阻止服务器配置编辑、删除。清理意图必须先持久化，保存失败时不执行；已清理但结果保存失败时页面会同时保留清理结果和存储告警。

清理仅逐个删除已核验的普通 Ethash DAG 文件，并拒绝符号链接、硬链接、未识别文件、进程仍占用或检查期间发生变化的缓存。链数据库、`SN`、keystore、账户地址、证明密钥、日志及实验/交易记录均保留；再次挖矿时需要重新生成 DAG。页面按文件实际分配的块估算释放量，部分成功逐项显示，实际可用空间以清理后的文件系统检查为准。worker 应使用专用目录；其他 Unix 用户不可见的进程以及 Lab 外部管理员操作不受控制面的互斥锁管理。

### 节点日志轮转

控制器每分钟尽力检查已记录节点的 `geth.log`，达到 64 MiB 后保留当前文件并轮转为 `.1`、`.2`、`.3` 三份历史日志；旧归档被后续轮转替换。只管理节点日志，不管理控制器的 `lab/data/server.log`。64 MiB 是触发阈值，不是硬容量上限：节点涉及排队、执行中、等待确认或待核验交易，或正在恢复、调整矿工等操作时会延后轮转。

轮转采用 copytruncate 保留 geth 已打开的日志 inode，复制与截断之间可能丢失少量并发写入的日志；节点无需为轮转而重启。归档还需要额外空闲空间，不足时记录告警并保留原日志。性能解析按旧到新读取仍保留的 `.3`、`.2`、`.1` 和当前日志，已采集到数据库的证明及交易指标不受归档删除影响；尚未采集且已超出保留范围的原始记录无法回填。

## 推荐实验流程

1. 构建 `dist/pfap-runtime.tar.gz`。
2. 添加并检查所有服务器。
3. 新建实验，选择每台服务器的节点数和矿工数量。
4. 部署并确认节点为 `running`，peer 数、实际挖矿数量符合预期。
5. 对每个参与隐私交易的节点执行一次 `CreateAccount`。
6. 对付款节点执行 `Mint`。
7. 执行 `Transfer` / `Redeem`，或启动自动规则。
8. 核对账户状态、Receipt、区块号和阶段耗时。
9. 导出实验 JSON 报告。

不要在同一个隐私账户上并发执行 ZK 状态交易。控制面为每个节点维护互斥锁；Transfer 会同时锁住付款方与接收方。Receipt 确认后还会等待新区块，避免下一笔交易在节点隐私序列状态尚未稳定时启动。

入队时还会检查所有参与节点：存在 `queued / proving / submitted / unknown` 交易时，手动请求返回冲突，自动负载跳过本次投递并等待后续周期。`unknown` 表示执行结果待核验，核验完成前保留节点占用。

### 继续实验与停止结果

“继续实验”使用已保存的 `artifactSha`、节点实际 `runtimeSha` 和原 datadir；更新 `dist/pfap-runtime.tar.gz` 不会改变旧实验的运行包。恢复包仍遵循上文的兼容性限制。缺少原运行包、链数据或账户时会显示具体错误，不能通过继续实验创建新链。需要使用新运行包开展实验时，请新建实验。

停止实验时，控制面逐节点核对进程身份、原目录和运行包，再请求退出并确认结果。某台服务器不可达或某个进程的归属无法确认时，其节点显示“未确认”，实验显示 `stop-failed`；其他可访问节点仍会继续执行停止检查。排除问题后可重试停止。停止未确认和中断状态仍锁定服务器连接配置及实验删除操作。

停止实验会取消尚未开始的交易，执行中的交易转为待核验，并停止自动规则新增投递。控制器重启中断部署、恢复或停止时，实验显示 `interrupted`，可以按原目录继续或重新检查停止。

### 矿工选择与出块可用性

实验可以配置 `1..节点总数` 个矿工，并选择自动或手动模式。新实验默认自动模式、2 个矿工（只有一个节点时为 1 个）；升级不会重分配已有实验的角色，旧单矿工实验仍保留原基线。

自动模式优先在不同宿主机分组之间轮流选择，再在同组的服务器及节点之间轮流选择；分组名去除首尾空格、比较时不区分大小写。未填写归属的服务器仍按服务器配置分散，但页面明确提示归属未知，不能算作已确认的物理主机隔离。更改宿主机归属后，需要明确应用矿工配置才会重新分配已有实验。

手动模式直接选择具体节点，数量由选择结果计算。配置持久化为 `minerMode: "manual"` 和 `minerSelections: [{serverId, localIndex}]`；这里的 `localIndex` 是该服务器内部的节点序号，页面同时显示实验全局节点名称以避免混淆。使用稳定部署位置而非尚未生成的账户地址，可在新建实验前完成选择。后端拒绝空选择、重复选择或不属于实验的节点。首次部署、磁盘预检、在线调整使用相同规则；按原目录恢复保留已保存的矿工角色，不会悄悄改回自动分配。

“实验”详情支持保存草稿/停止实验的矿工选择，也支持对运行中实验点击“应用矿工配置”，不重启节点、不清空链、不重新发送交易。部署时先启动所有节点并建立拓扑，再启动矿工；在线调整时先启用并确认目标矿工，再停止被移出的矿工。配置中的角色与实际 `eth.mining` 分开展示，不可达或尚未采样的节点不计入在线挖矿数量。`eth.mining=true` 表示挖矿工作已启用，并非保证已经产出区块，还需观察链高度和 peer 连接。

在线调整失败可能只部分生效，页面会保留目标配置、错误和实测状态，可排除故障后重试相同数量。涉及角色变化的离线节点必须先恢复；恢复、启停和矿工调整不能同时执行。控制器重启中断配置时也会明确显示未完成，不自动重试命令。配置及操作事件随实验报告导出。

只有 1 个矿工时，该节点掉线会暂停出块及交易确认，但不意味着实验数据丢失。多个相互连通、正常挖矿的节点可让其余节点在一个矿工掉线后继续出块；已经故障的交易参与节点仍需单独恢复。要减少主机故障的影响，应把至少 2 个矿工放在不同物理服务器上。

增加矿工也会改变 CPU/内存/DAG 开销、总算力、出块节奏及分叉概率；运行中修改会改变统计基线，严谨对比应使用不同实验并保留配置记录。本功能是出块冗余，不是完整的生产级高可用保证：网络分区、全部矿工失联、磁盘损坏仍会影响实验；当前 PFAP 全局 SMT 在运行中链重组/候选块回滚时的隔离限制仍存在，多矿工隐私交易实验需额外核对链与账户状态。

API：创建及调整均支持自动模式 `{"minerMode":"auto","minerCount":2}` 或手动模式 `{"minerMode":"manual","minerSelections":[{"serverId":"srv-a","localIndex":2},{"serverId":"srv-b","localIndex":1}]}`。调整使用 `POST /api/experiments/{id}/miners`，显式填写的模式只接受 `auto` / `manual`，不接受空字符串。旧的仅传 `minerCount` 的请求仍兼容自动模式，同数量重试保留现有角色；不能用这种旧请求覆盖手动模式。运行中返回 `202`，仅表示操作已接受，应继续检查 `miningStatus`、`miningError` 与节点实测 `mining`。

### 实验中途节点掉线与恢复

`unreachable` 表示控制面无法访问节点 IPC，不一定代表服务器离线。先查看“服务器”的连接状态；服务器关机、SSH 不通或磁盘满时，要先恢复主机条件。

实验仍处于 `running` 时，可以在“实验”的节点行，或“交易”的账户卡片点击 **恢复节点**。该操作会：

1. 核对原 runtime SHA、datadir、账户和端口；缺少原数据时拒绝创建新链。
2. 只对已退出的进程执行原地启动。进程尚在但 IPC 不可用时保留进程并显示日志，不强制终止证明计算。
3. 重建节点间连接；按照实验配置恢复矿工的出块角色，不再固定为 node-1。
4. 查询原账户与链状态，保留交易记录，不再次执行 CreateAccount，不重发任何交易。

恢复还会核对已初始化账户是否仍能查询到有效链上隐私状态；异常时显示独立错误并暂停该节点的隐私交易，Public 交易不受隐私状态检查影响。修复后的 geth 支持原 SN 文件中的空 SNS 字段，并在读取损坏的非空 SN 文件时直接报错退出，避免静默使用初始账户状态。

修复版还会在开放 RPC/启动挖矿前，从已确认的规范链重建进程内承诺树（SMT），只恢复公开承诺，不重放余额、不重新广播交易。账户查询返回 `commitmentReady`；恢复后的账户若未通过此检查，将保持隐私交易保护。这里处理的是启动恢复，不解决原有全局 SMT 在运行中发生链重组、候选块回滚时的隔离问题。

恢复中的节点不会接收新的手动或自动 Transfer/隐私交易；恢复失败会保留可展开的错误详情，排除问题后可重试。控制器重启中断恢复任务时会解除“恢复中”状态，允许重新检查。恢复期间不能同时停止实验。

历史实验默认仍由 node-1 单独出块，可在实验详情中调整矿工数量；恢复后应检查链高度继续增长、peer 数恢复。自动负载只跳过暂不可用节点的投递，不会补发跳过的次数。已经广播但未确认的交易应先核对原 hash 的 Receipt；中途失败的 Transfer 还应核对双方状态。控制器重启后，未开始的交易会取消，可能已经执行的交易转为待核验，自动规则停止新增投递。

### 待核验交易

控制面会在执行 RPC 前保存执行意图，获得交易哈希后立即保存哈希。RPC 断连、未返回哈希或 Receipt 查询超时，均不能单凭这些现象判定链上失败，页面会显示“待核验”。

有哈希的待核验交易会定期查询，也可点击“核验结果”。核验只读取 Receipt 和对应主链区块；交易哈希、区块哈希和执行状态一致后，才保存成功或链上回退结果并解除交易占用。没有 Receipt 时继续保持待核验。核验后的 `confirmedAt` 是控制面观察到结果的时间，可能包含离线时长，不能据此推断实际打包时刻。

没有交易哈希时无法自动确定是否发送成功，需人工核对节点日志、主链和双方账户状态。控制面不会自动补发或调用隐私状态回滚，也不会仅凭超时解除该交易对节点的占用。

**旧运行包限制：** 独立的隐私账户 `AccountSK` 只在进程内存中，`SN` 文件保存序列、随机数、承诺与余额，但不保存该秘密。原地恢复后旧代码会使用默认回退逻辑，页面会对已初始化账户显示提示。这不等于账户一定不可用，也不代表已验证隐私交易连续性；不要为此再次 CreateAccount 或删除数据。可靠的隐私账户灾难恢复还需要运行包增加秘密的原子持久化、加载与崩溃一致性处理。

## 交易与执行指令

交易表单会在提交前实时显示实际执行计划。提交后该计划保存到交易的 `command` 字段和实验报告。

```javascript
eth.sendCreateAccountTransaction({from: eth.accounts[0]})
eth.sendMintTransaction({from: eth.accounts[0], value: "0x100"})
eth.sendRedeemTransaction({from: eth.accounts[0], value: "0x1"})
```

Transfer 是两阶段操作：

```javascript
// 付款节点：生成 proof，并暂存下一本地状态
JSON.stringify(eth.getPayerNextState("0x01", "0x1"))

// 接收节点：带入付款方输出并广播最终交易
eth.sendTransferTransaction({
  from: eth.accounts[0], value: "0x1", rs: "0x01",
  cmtANew: payer.cmtANew, snAOld: payer.snAOld, proofA: payer.proofA
})
```

Transfer 前会即时查询双方账户。付款方必须完成 CreateAccount + Mint，接收方必须完成 CreateAccount，双方当前 commitment 必须已进入全局状态 Merkle 树。付款方生成状态包后发生断连，或接收方提交结果不确定时，控制面保留待核验状态，避免在交易可能已上链时错误回滚本地状态。

## 账户与交易页面

账户状态已合并到交易工作区。选择实验后可查看：

- 节点账户地址、公开余额（wei）、隐私余额（十六进制和十进制）；
- commitment、隐私状态所在区块；
- 当前链高度、peer 数、最后查询时间；
- 账户状态变更历史；
- 交易指令、哈希、Receipt 与性能阶段。

每个节点支持手动即时查询；交易确认后自动刷新发送方和接收方。

页面通过 SSE 和 5 秒兜底轮询获取状态，但使用增量 DOM 更新：不变的表单、选项和卡片不会重建，高频区块字段只修改文本，刷新请求会去重且不会并发。Receipt 展开状态和正在编辑的表单值应保持不变。

## 自动交易

自动规则当前支持 `round-robin`：

- Mint / Redeem：依次选择执行节点；
- Transfer / Public：`node[i] -> node[(i+1) % N]`。

每笔自动交易保存 `workloadId` 和 `sequence`。页面可展开查看实际发送节点、接收节点和最终状态。达到规则时长后只停止投递，规则进入 `draining`；所有已投递交易最终结束后才变为 `completed` 或 `completed-with-errors`。

可随时点击“停止投递”。该操作停止后续入队，已接受的交易继续执行或等待核验；实验停止则会进一步取消未开始的交易。规则显示尝试次数、实际入队数、节点忙跳过数和节点不可用跳过数；实际投递速率按入队数除以投递时间计算，结束时长由 `submissionStoppedAt` 固定。

PFAP 证明通常远慢于投递间隔。节点繁忙时自动规则会跳过本次尝试，并按下一周期继续轮询，不补发跳过次数。正式实验应根据交易类型设置合理速率，同时观察实际入队率和跳过次数。控制器重启后规则显示“已中断”，不会自动续投。

## 状态保存与故障详情

状态更新先在副本上完成，再同步写入临时文件并原子替换主文件；保存失败时不会把尚未落盘的修改发布为当前状态。`lab.json.bak` 保存上一次成功写入的快照。主文件损坏时不会自动回退备份，避免把较旧交易状态当作最新事实。

页面显示状态存储健康情况。保存失败时检查磁盘空间、目录权限和文件系统；启动阶段无法保存状态时，控制面拒绝新的操作，需要修复后重启。备份恢复应先停止控制服务、保留当前文件并人工核对链上结果，不能仅恢复旧 JSON 后重发交易。JSON 存储仍只支持一个控制进程。

服务器检查失败时保留最后一次成功获取的负载数据，并同时展示当前错误和最后成功时间；这些数据在服务器恢复前仅代表历史采样。

## 性能字段与统计口径

| 字段 | 含义 |
| --- | --- |
| `submittedAt` | 请求进入 Lab 队列的时间（历史命名，实际是 queued time） |
| `provingAt` | 获得节点锁并开始执行/生成证明 |
| `broadcastAt` | 获得交易哈希、广播完成 |
| `confirmedAt` | 观察到链上 Receipt |

时间分解：

- 排队：`provingAt - submittedAt`
- 证明：C++ `gen ... proof Use Time`，无法提取时使用阶段墙钟时间
- 验证：C++ `verify ... proof Use Time`
- 链上确认：`confirmedAt - broadcastAt`
- 端到端：`confirmedAt - submittedAt`

原始精度使用 `proofDurationUs` / `verifyDurationUs` 保存。页面按量级显示 `µs`、`ms` 或 `s`，不会把亚毫秒值截断为 `0 ms`。控制面通过交易哈希在对应节点 `geth.log` 中定位计时边界，并在启动时为历史单节点 ZK 交易回填微秒数据。

新版 runtime 还记录交易构造和交易验证标记。Transfer 分别保存付款端和收款端的证明生成、证明验证、交易/状态包生成及交易验证；旧 runtime 没有带交易哈希的验证标记时显示为空，不使用 Receipt 等待时间代替。执行 `./build.sh keys` 或 `./build.sh all` 会生成 `dist/build-profile.json`，记录密钥耗时、pk/vk 大小以及构建主机和工具链。生成新密钥会改变证明参数，不能为了补历史数据在运行中的网络上随意执行。

总览 TPS 是整个已保存历史区间的平均值，已标为“历史平均 TPS”；它不等同于某次负载的稳态吞吐。正式结论应按实验、交易类型和 workload 分组，报告样本数、成功率、排队/证明/验证/链上确认的 p50/p95/p99。

### 隐私账户初始化

节点部署时创建的是普通 EOA 地址。参与 Mint、Redeem 或 Transfer 前，每个节点还需要在当前实验链上成功执行一次 CreateAccount。交易页提供“一键初始化”，只为尚未初始化、状态正常且没有活动交易的节点排入一次 CreateAccount；同一服务器上的初始化串行执行，不同服务器可并行。重复 CreateAccount 会重置节点本地隐私状态，因此单笔接口也会拒绝已初始化节点，自动交易规则不提供 CreateAccount 类型。

初始化不会在部署后静默运行，因为它会产生真实交易并进入实验性能统计；Public-only 实验也不需要这一步。对于全新的隐私交易实验，应在开始 Mint/Transfer/Redeem 前显式执行一次批量初始化。同一实验停止再启动时会自动识别已有链上状态并跳过。

## Web 安全

- 密码来自 password file；登录后使用 HttpOnly、SameSite Cookie；
- 不要提交 `lab/data/password`、`lab/data/lab.json` 或 SSH 私钥；
- 局域网监听不等于公网安全，公网必须增加 HTTPS、访问控制和审计；
- 服务器配置保存 SSH 私钥路径，不复制私钥内容。

## Native 与 Docker

推荐混合策略：正式性能实验使用宿主机 native worker，避免 bridge/NAT、overlay filesystem、cgroup 和容器调度噪声；Docker 适合功能回归、CI、快速清理和高节点数 smoke test。当前已实现 native local/SSH executor，尚未实现 Docker executor。

## 已知限制

- JSON 状态存储只适合单控制进程、单用户；多用户应迁移到 PostgreSQL。
- 支持停止自动投递，但不提供强行取消已发送交易、盲目重试或细粒度 RBAC。
- 自动规则没有自适应速率；高于节点能力时会跳过投递，需关注实际入队率。
- 指标筛选和图表仍需加强，尤其是 workload 稳态 TPS、p99 和时间序列。
- `lab/scenarios/*.json` 是设计样例，尚未提供场景导入执行器。
- Docker worker 尚未实现。
- 控制服务重启不会停止 geth；会恢复 running 实验监控，但登录需重做。

开发交接、关键源码和当前验证状态见 [`DEVELOPMENT_HANDOFF.md`](DEVELOPMENT_HANDOFF.md)。
# 自动实验流程（2026-09）

交易页的“自动实验流程”默认使用完整 Transfer 模式，传统 Mint / Redeem / Public 定时测试保留在流程下拉框中。操作顺序：

1. 先启动实验，选择交易节点和区块观察节点。建议观察节点不参与挖矿，宿主机资源独立。
2. 点击“初始化所选未开户节点”，确认后仅为未初始化节点发送 CreateAccount；等待交易结束与状态刷新。
3. 填写目标隐私余额，点击 Mint 补足。仅补差额；整批准入原子检查，不会在正式运行中自动补款。公开余额需自行提前准备，含手续费。
4. 设置持续饱和 / 目标速率、预热时间、测量时间和确认深度，执行准备检查，再明确确认启动。
5. 预热至少达到指定时间、所有参与账户都完成过安全交易，且观察到至少两个区块后进入独立测量窗口。最长额外预热 30 分钟，未满足则停止投递。该资格检查不是统计平稳性的证明，请检查报告的每分钟吞吐和资源监控。
6. 到达测量结束时间停止新增投递，继续收尾；手动提前停止、状态异常、区块采集失败 / 重组均不能标记为完整有效窗口。未确认交易不会自动重放。

调度按最长空闲付款账户优先、低余额收款账户优先进行确定性排序。两账户在同一持久化事务中预留，确认前不得再次参与交易。Transfer 成功 Receipt 进入 `settling`，核验双方交易哈希、相同规范链区块、确认深度、当前承诺已入树、状态所在区块及预期双方余额后才标记 confirmed / ReadyAt。核验超时不释放账户；交易记录中可再次只读核验。控制器重启中断运行，不自动续投，settling / unknown 占用保留。直接绕过 Lab 使用外部 RPC 仍可能破坏约束。

报告 API：`GET /api/workloads/{id}/report`。包括独立窗口的观察确认 TPS、测量提交批次延迟分位数、未完成数、分钟序列、区块指标、原始区块样本和启动配置快照。预热提交但窗口内确认计入窗口吞吐，不计入测量提交批次；窗口内提交、收尾才完成的交易计入该批次延迟，不延长窗口分母。

区块由指定观察节点每 5 秒采集，按控制器观察时刻归窗，边界有采样误差；连续区块的头时间戳用于间隔，大小为客户端返回的编码字节数。重组 / 漏采标记窗口无效，不提供 PoW 最终性保证。`PFAP_BLOCK_EXECUTION_VALIDATION` 埋点测量 Process + ValidateState，排除共识头验证、网络、状态数据库提交；本地挖出的区块可能不经过这一导入路径，缺失样本为 null 而不是 0。旧 geth 包无此埋点，需要使用新 runtime；不能把该字段称为完整区块验证耗时。

账户就绪核验验证链上与内存匿名状态，不构成 SN 文件 fsync 或崩溃一致性的证明。当前 JSON store 和 SSH 采集本身存在开销，高负载结果应结合控制器与宿主机负载解读；单次运行不等于完成可靠性 / 安全性验证。
# 自动实验的节点角色

部署使用规模相关的总时限：15 分钟 + 每台服务器 3 分钟 + 每个节点 2 分钟；这是故障保护上限，不是预计耗时。上传单步最多 10 分钟，普通远程阶段与部署 IPC 配置最多 2 分钟，单台启动最多 5 分钟 + 每个本地节点 1 分钟。超时明确提示阶段并进入核验清理，不自动重复发送。停止总时限至少 20 分钟，按每节点 30 秒扩展；单节点停止仍最多 25 秒，不升级为强制杀进程。全连接 peers 按源节点批量设置，减少 SSH 次数，但连接数仍是平方规模。页面展示实际阶段与节点启动计数，不显示虚假的耗时百分比。

单个实验支持最多 300 个节点，部署规划、矿工选择、停止清单重建及完整自动实验的节点选择使用相同上限。服务器批量管理仍按每批最多 100 台执行，可以分批录入；此限制不是实验的节点总数限制。请根据实际资源规划规模，300 是配置容量而非已验证的性能保证。

自动实验采用矿工与交易节点分离：矿工继续出块、验证区块和其中的交易，但不作为自动交易的付款方或收款方。完整实验至少需要一个在线矿工和两个在线非矿工；交易节点必须已采集到明确的非挖矿状态。配置为矿工但暂时未挖矿的节点也不会进入交易池。

账户准备、预检查、调度和实际发送均检查节点角色。运行中角色变化会停止新增投递并进入收尾，不提前解除在途匿名交易的账户占用。旧版自动调度也排除矿工；手动测试仍可选择矿工，但不能干扰正在进行的完整自动实验。

这种分离用于减少挖矿与证明计算的资源竞争，便于归因，并不意味着真实以太坊矿工不能发送交易。LXC 容器共享宿主机时仍存在资源竞争，建议矿工与交易节点分布在不同宿主机，并在结果分析中保留部署拓扑。
