# 一键运行 100 节点实验

更新：2026-09-12。

入口为 `lab/scripts/run-experiment.cjs`，封装已有 `run-live-hour.cjs`。
一条命令完成既有部署的检查、可选恢复、账户准备、预热、一小时测量、收尾、导出与停止。
它不是服务器发现、创建实验或首次部署工具，不会默认选择“最新实验”，也不会覆盖旧实验目录。

## 前置条件

- 在控制器主机执行，Node.js 18 或更新版本；Lab 已监听 `127.0.0.1:8090`。
- 密码位于 `lab/data/password`，不会打印或写入报告。
- Web 中已部署好目标实验：100 个不同服务器配置，每个一个进程；5 个专用矿工，分布于 5 个明确标记且不同的 `hostGroup`；1 个 `host=local` 的非矿工观察节点；94 个非矿工交易节点。
- 实验正在运行，或已正常停止且命令明确传入 `--start`。停止失败、未部署和中断部署需先人工处理。
- 默认读取 `dist/pfap-runtime.tar.gz` 计算 SHA-256，并核对实验包及全部节点版本。也可传入事先核实的 `--runtime-sha`。计算哈希只核对版本一致性，不证明包可信或代码正确。
- 无活动自动运行、无未解决交易，且目标服务器未被另一个运行/部署/恢复/停止中的实验占用。
- 执行期间不要同时在 Web、另一个控制器或外部 RPC 操作同一实验。

## 使用

在仓库根目录执行。也可通过脚本绝对路径从其他目录执行。

先进行只读预检查（`--start --check` **不会恢复节点**）：

```bash
node lab/scripts/run-experiment.cjs --experiment exp-c17eebe55019 --mode prepared --start --check
```

确认后，一条命令复用已完成账户准备的实验：

```bash
node lab/scripts/run-experiment.cjs --experiment exp-c17eebe55019 --mode prepared --start
```

`exp-c17eebe55019` 是现有实验的明确目标，复制此命令会在其原链上开始新一轮测量，不是创建独立新链。不同目标请替换 ID。

新部署、没有任何交易或运行记录的实验使用：

```bash
node lab/scripts/run-experiment.cjs --experiment exp-YOUR_ID --mode fresh
```

其中 `exp-YOUR_ID` 是占位符，须替换为 Web 中实际 ID。`fresh` 会发送 Public 资金、CreateAccount、Mint；`prepared` 只复用已确认准备，不重复开户、不自动补余额。准备过程中断后不能随意切换模式绕过检查；先核查已接受交易。底层 `--resume-preparation` 是带原目录标记的维护入口，不属于此一键入口，使用前需人工审查。

## 实际流程与进度

1. 检查布局、版本、服务器占用和历史交易；`--check` 到此结束。该检查不保证稍后网络、余额和账户样本仍就绪。
2. 只有明确传入 `--start` 才恢复已停止的原实验，不重置目录。
3. 等待 100 节点在线、各 99 peers、区块高度至少 12；再次核对布局及版本。
4. `fresh` 的 Public / CreateAccount 按宿主机分散、每批至多 5 个并行任务准备，Mint 串行；等待确认与账户新鲜状态。准备时间不计入一小时。
5. 94 个交易节点使用 ready-pool 饱和调度，Transfer 金额 1。不同账户对可以并行，每个账户只能占用一笔交易，付款和收款双方确认且安全就绪后才释放。
6. 预热至少 600 秒，并满足全部参与账户就绪、区块观察等资格条件，随后正式测量 3600 秒；确认深度 6。过期/临时不可用空闲节点暂停准入，不解除在途账户锁。
7. 测量结束停止新增投递，等待收尾。只有运行完成且报告 `completeWindow=true`，才进入正常停止流程。
8. 导出报告，停止并核验全部节点，再导出最终状态；退出码 0 才代表上述流程全部完成。

因此“一小时”是正式观察窗口，不是命令总耗时。资格预热不自动证明统计平稳；饱和模式也不保证始终有 47 对并发。

命令开始打印独立结果目录 `lab/data/one-click-100.XXXXXX/`。另开终端查看：

```bash
tail -f lab/data/one-click-100.XXXXXX/progress.log
```

请替换为实际目录。日志包含网络就绪数、账户准备计数、阶段、投递数量及测量起止时间，不提供虚假的总百分比。长任务可在已有 tmux 会话中执行，避免 SSH 断开中断前台脚本。

## 成功、失败与恢复

每次执行创建 `status.json` 与 `RESULT.md`，正常结束更新为 `completed`，可捕获错误更新为 `halted`。预检查不写执行文件；参数错误在执行前退出。

- 成功：生成单次运行及整个实验的 HTML、JSON、CSV ZIP；报告含指标解释、原始样本与限制。`RESULT.md` 链接实际已导出的文件。
- 常规运行失败：底层脚本尽力分别导出各格式报告，某个格式失败不阻断其他格式尝试；登录失败/服务不可达可能无法取得报告，日志会记录原因。报告存在不等于有效窗口。
- API 写请求超时后不自动重试：服务端可能已经接受请求。即使没有 `run-id.txt`，也要在 Web 检查运行与交易，不能假定“没启动”。
- 异常默认**不自动停止节点、不取消在途交易、不回滚匿名状态**。先检查 `progress.log`、Web 运行及交易详情；必要时只读核验原交易，再由用户决定停止或恢复。
- 同一入口通过实验级目录锁避免双开；它不能阻止 Web、底层脚本或其他控制器的并行操作。
- Ctrl-C / SIGTERM 在子脚本运行期间会结束本地子脚本并标记失败，但不撤销远端已接受任务，且不能保证导出报告。断电、SIGKILL 或进程在准备入口阶段被杀时可能留下 `running` 和锁目录，**不能当作完成**。
- 遇到 `one-click-exp-….lock` 已存在，先读其 `owner.json` 核对 PID/结果路径，并检查进程及 Web 活动任务。只有确认没有本地执行者、没有待处理远端操作，才人工移除该锁的 `owner.json` 及空目录；禁止脚本自动清理“看起来过期”的锁。

实验数据、报告、密码和锁位于被 Git 忽略的 `lab/data`；结果需自行备份，不随代码提交。
