## 已发现的问题

- 四种匿名证明的 PK 缓存被再次复制到临时 keypair，生成函数还按值接收 PK。改为线程安全的只读局部静态缓存，函数按 const 引用接收。
- Mint、Redeem、CreateAccount 及部分公共辅助函数遗漏释放 C 字符串或 C++ 返回缓冲区。CString 用 C.free；new[] 返回值用 smtFree（delete[]），不混用分配器。
- 历史 SMT 快照原来完整复制 map；每个节点键用逐位字符串保存。快照数量上限不能限制每份树随历史增长的空间。改为不可变节点及路径复制，快照共享未变的子树；丢弃最后一个引用时自动回收。没有改变树深、Poseidon 哈希、路径顺序、根编码或验证规则。
- 大型原生证明分配固定到每个进程自己的 OS 工作线程，避免不同 Go 调用线程各自保留计算内存。只串行该节点内的证明生成，不串行整个网络，也不串行证明验证；调用同步返回，panic 回传调用方。线程一致性、并发串行与异常后继续执行有 race 测试。
- PK/VK 缓存首次加载改用 C++ 线程安全的局部静态初始化，避免手写 `loaded` 标志的并发竞争；不重新生成密钥。

这些是可从代码确认的问题，但不能仅凭它们断言此前 SSH 超时一定由 OOM 引起。重启后 OOM 计数清零不构成重启前没有 OOM 的证据。

## 验证方法

修改前从 map 实现采集空树、1/2/16/32 条记录的根和 witness 摘要，写入 `go-ethereum/zktx/smt_compatibility_test.go`。新实现必须逐字节兼容，并测试重复插入、分叉、释放原树后继续使用克隆。

```bash
BUILD_JOBS=2 bash scripts/build-compatible-runtime.sh
bash scripts/test-transfer-history.sh -vet=off -run 'TestSMT|TestTransferCMTS|TestTransferHistory|TestTransferRequires' -count=1
PFAP_TEST_MEMORY_SOAK=1 bash scripts/test-transfer-history.sh -vet=off -run '^TestSMTSnapshotMemorySoak$' -v -count=1 -timeout 15m
PFAP_TEST_MEMORY_SOAK=1 PFAP_TEST_REAL_PROOFS=1 PFAP_TEST_MEMORY_ROUNDS=10 bash scripts/test-transfer-history.sh -vet=off -run '^TestNativeProofMemorySoak$' -v -count=1 -timeout 45m
```

旧版 geth 测试中的格式字符串检查与当前 Go vet 不兼容，因此上述历史代码测试显式关闭 vet；这不是跳过编译或测试。Lab 测试仍正常执行 `go test ./...`。

内存测试不连接实验节点，不读取账户私钥，不广播交易；生成随机测试状态，用现有 PK/VK 验证真实证明。报告 `/proc/self/status` 的 RSS、峰值和 swap，不能只看 Go 堆，因为原生分配不在 Go 堆内。

快照测试使用 5,000 条记录及四份各增加一条记录的克隆，检查内存增量不超过 16 MiB。证明测试默认十轮，每轮付款/收款两个有效证明，并检查错误根及不匹配 witness 被拒绝。证明测试输出趋势，不把测试进程的占用直接当作完整 geth 的容量要求。
