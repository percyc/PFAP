## 实现与不可混淆的边界

- `eth/peer.go`：对 Transfer 的成功 `p2p.Send` 记录调用开始时间，多个 peer 取最早成功发送的开始时间。这是应用层开始广播，不是网卡硬件发包时间；失败发送不作为原点。
- `core/blockchain.go`：规范链写入成功、更新本地头后立即取时间。以同一收款节点 Go 单调时钟求广播到本地首次规范链收录的间隔，不用跨服务器墙钟相减，也不等到控制器轮询和账户六层就绪。
- 传播、等待打包、PoW、本地导入是确认路径的真实开销，不扣除。日志中携带交易和区块哈希；汇总核验最终规范链 Receipt，出现被替换区块的首次收录则拒绝合并为正常样本。进程重启后单调时钟不能跨进程延续。
- `core/tx_pool.go`：从 `validateTx` 入口到成功校验结束，按节点、交易哈希只记录第一次成功校验。包括基础规则、历史根、序列号及双方证明检查；不含进入该函数之前的池锁等待、网络等待或失败尝试。汇总仅选本实验专用矿工，不掺入付款/收款方样本。先对每笔交易的矿工样本求均值，再对交易求均值。
- `consensus/ethash` 记录真实 header worker 的有效工作时间，包括 seal/PoW；区块导入分别记录 ValidateBody（含叔块）、父状态读取及 Process + ValidateState。各阶段时间相加，排除并行 header worker 队列等待和数据库提交，不冒充单段端到端墙钟。必要的数据读取仍计时。客户端原有并行发送者签名预取缓存不在这些阶段内，已有日志等节点运行开销也不是通过事后减常数消除。
- 区块验证仅选矿工导入其他节点区块的成功样本；自己产出的区块不填零。按矿工＋区块哈希去重，先求每个区块在矿工上的均值，再对窗口内区块平均。缺少 header 样本不降格填成旧的 Process + ValidateState。
- 窗口按规范链区块头时间戳属于 `[measurementStartedAt, measurementEndsAt)` 划分，而不是控制器采样时刻。区块计数与大小包含空块，间隔按连续头时间戳计算。区块头时间不是发现 PoW 解的精确时间，也不能用它反推单笔交易传播延迟。
- 延迟与准入验证使用正式阶段提交的 Transfer 批次，收尾完成的交易仍属于该批次。P90/P95 使用排序后零基下标 `floor((n-1)*p)`，不插值。

## 采样、导出与安全

`pfapmetrics` 输出 `PFAP_MEASURE` JSON 行，仅含进程会话、哈希和时间数据，不含账户秘密。内存表各最多 32768 项，溢出显式记录，汇总拒绝该样本集；本模块不写共识或匿名状态，不自动解锁、重发交易或回滚。

实验成功收尾并导出后运行：

```bash
node lab/scripts/summarize-node-metrics.cjs lab/data/measurement-20m.ACTUAL_DIRECTORY
```

替换为实际证据目录。该命令只读节点保留日志，生成 `node-metrics.json`、`summary.json`。它检查规范链连续性、重组、进程会话与采样覆盖；`completeSamples=false` 不能宣称八项全部有效。新简表独立于旧 Web 报告，尚未将这套新指标接入页面。

基础验证：`GO111MODULE=off go test -race ./go-ethereum/pfapmetrics`；`node --test lab/scripts/summarize-node-metrics.test.cjs`。兼容运行包构建通过，8 个 pk/vk 与旧已部署版本逐文件 SHA-256 相同。
